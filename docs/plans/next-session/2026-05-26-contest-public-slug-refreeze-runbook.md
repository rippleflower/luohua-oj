# Contest Public `slug` Re-Freeze Runbook

## Why

The contest public detail payload now includes `problems[].slug`.
Older rows in `contest_public_details.problems_json` may still use the legacy shape without `slug`.
Those rows must be regenerated by running contest freeze again.

## Scope

This runbook only refreshes contest public read models.
It does not alter contest/problem core entities or submission records.

## 1) Identify affected contests

Run:

```bash
psql "$DATABASE_URL" -f scripts/contest-public-slug-refreeze-check.sql
```

Take the `id` and `slug` rows from the first query as the re-freeze target list.

## 2) Re-freeze each affected contest

Use one of these methods:

1. Admin UI:
   - Open admin contests page.
   - Locate the target contest by `slug`.
   - Trigger freeze with reason: `refresh contest public problem slugs`.
2. Admin API (authenticated session + CSRF):
   - `POST /admin/contests/{contestID}/freeze`
   - JSON body:

```json
{
  "reason": "refresh contest public problem slugs"
}
```

## 3) Verify completion

Run the same SQL script again:

```bash
psql "$DATABASE_URL" -f scripts/contest-public-slug-refreeze-check.sql
```

Expected:

- first query returns no rows
- second query returns `0` for `contests_missing_problem_slug`

## 4) Spot check from public API

For one refreshed contest:

```bash
curl -sS "$API_BASE_URL/contests/<slug>" | jq '.problems[0]'
```

Expected:

- `slug` exists on problem entries
- existing fields (`code`, `title`, `difficulty`, `status`) remain intact
